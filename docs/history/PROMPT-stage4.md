## Goal
Stage 4 of the spike (stages 1–3: `PROMPT.md`, `PROMPT-stage2.md`, `PROMPT-stage3.md`, all summarised in `NOTES.md`).
Add an **edge** tier that mimics Fly.io's anycast edge, and move routing out of the workers:
- 2 edge instances share one address (`127.0.0.1:80`) via `SO_REUSEPORT`; the kernel spreads connections
  between them, standing in for anycast.
- The edge routes `<app>.flyyy.localhost` round robin over **all** of that app's VMs, across all workers.
  It reads them from Corrosion, using the same in-order, no-gap subscription loop as stage 3.
- The edge reaches a VM only through a **backhaul** to the VM's worker. The worker proxy no longer
  routes by vhost: it validates the requested target, connects to the VM and pipes bytes.
- VMs are no longer reachable directly from the host.

## Target topology (changes from stage 3 in bold)
host
├── containerd + devmapper (unchanged)
├── **2 × nspawn edges (`edge1`, `edge2`), `privateNetwork = false` (host network namespace)**
│   ├── **corrosion agent: joins the worker cluster (5 agents in total)**
│   └── **edge.service: `127.0.0.1:80` with `SO_REUSEPORT`, HTTP/1.1, vhost → RR over all VMs of the app,
│       each request through the target worker's backhaul; a debug `/state` endpoint on a per-edge port**
└── 3 × nspawn workers
    ├── corrosion agent (unchanged)
    ├── **proxy.service → backhaul: listens on `10.99.N.2:<backhaul port>`, accepts only targets that are
    │   instances of this worker (from its own stage 3 subscription), connects, pipes bytes**
    └── Firecracker VMs (unchanged: whoami a/b on all, echo c/d on worker1+2), **no longer routed from the host**

## Backhaul (edge → worker)
- **HTTP `CONNECT <instance-id>`** (for example `CONNECT worker1-a HTTP/1.1`) to the worker's backhaul port,
  via hyper's upgrade support on both sides. No hand-written protocol and no HTTP parsing of our own.
- The worker resolves the id with its own live table (id → `addr`), so the edge never learns VM IPs and can't make
  a worker dial an arbitrary address. Unknown id, or an instance of another worker → 403/404, and nothing is dialled.
  VM connect failure (1 s timeout, as before) → 502. Otherwise 200, then `copy_bidirectional` until either side closes.
- The edge sends the client's HTTP request over the tunnel with hyper's client handshake: Host is kept,
  `X-Forwarded-For` added, and a response header `X-Edge: edgeN` added so tests can tell which edge answered.
- **Fallback:** if CONNECT fails (connect error or non-200), try the next instance in the RR order, once round the list.
  This is safe because no request bytes were sent yet. All failed → 502.
- One backhaul TCP connection per request: no pooling or multiplexing.
  `// shortcut: one CONNECT per request, pool or multiplex (HTTP/2) the backhaul when load matters`.
- `// shortcut: plaintext, unauthenticated backhaul on the host-local transit network; Fly uses WireGuard`.
  **Target validation is not a shortcut: it is required.**

## Routing data
- Same `instances(id, worker, app, addr)` table and same writer (`up.sh` → worker1's agent). No schema change.
- Edge subscription: `SELECT id, worker, app FROM instances`, so the edge never sees `addr`. Vhost = `<app>.flyyy.localhost`,
  upstreams are all of the app's instances sorted by id, with one RR counter per vhost per edge.
- Worker subscription: unchanged (`... WHERE worker = ?`), now used as the backhaul allowlist.
- Worker → backhaul address: a static map passed to the edge as an argument, generated by Nix from the same worker table
  (for example `worker1=10.99.1.2:4280,...`).
  `// shortcut: static worker list; move it to a Corrosion table when workers can join`.
- Before an edge's first snapshot completes, it answers 503 (unchanged rule). Unknown vhost → 404, missing Host → 400.

## Code layout
- Same crate, one binary with two modes (`proxy edge ...` and `proxy worker ...`), so the stage 3 subscription loop
  (`session`/`follow`/`publish`) is shared, not copied. New dependencies only if unavoidable, following the
  repo's Rust dependency rule (latest exact version, `default-features = false`, explicit `features`, a comment).
- Edge and worker both log one line per request/tunnel: target id, worker, status, latency, and
  fallback attempts for the edge.

## Networking changes
- `up.sh` no longer adds host routes to `10.100.N.0/24`, and the workers stop enabling `ip_forward`.
  The backhaul is a local process in the worker, so nothing is forwarded.
- Edges share the host network namespace. So, in this namespace:
  - Their corrosion agents need distinct ports and an address the workers can reach (a host-side transit address such as
    `10.99.1.1`, or `0.0.0.0` with per-edge ports). Their APIs and `/state` endpoints go on 127.0.0.1 with per-edge ports.
  - Ports must not clash with each other or with the host.

## Success criteria (all must pass)
1. From the host, plain `curl http://whoami.flyyy.localhost/` (curl resolves `*.localhost` to 127.0.0.1) → 200 from a
   whoami VM. The same for `echo.flyyy.localhost` → only worker1/2 VMs.
2. **Round robin across workers:** with sequential requests, each edge's responses (grouped by `X-Edge`) cycle through
   all 6 whoami instances (and all 4 echo instances) in a fixed order.
3. **Both edges serve:** over ~50 new connections, both `X-Edge` values appear.
4. **Edge failover:** with `edge1`'s service stopped, all requests still return 200 (from edge2). After restarting it, both serve again.
5. **Direct access is gone:** from the host, `curl 10.100.N.x` fails, and the host has no route to 10.100.0.0/16.
   Inside the workers, `ip_forward` = 0.
6. **Backhaul validation**, from the host with curl `-p`/`--proxytunnel` or a raw CONNECT:
   - unknown id → 403/404;
   - another worker's instance → 403/404;
   - an IP:port target → rejected;
   - the worker logs show no dial in any of these cases.
7. **Fallback:** with `firecracker@a` stopped on worker1, all requests → 200, and `worker1-a` is skipped. With worker1's
   proxy stopped, all requests → 200 from the other workers. With all whoami VMs stopped → 502.
8. Each edge's `/state` equals its own agent's query. `storm.sh plain` (and `proxy-restart`, aimed at an edge) also audits
   both edges (gaps = 0) and checks `probe.flyyy.localhost` through the edge. Other storm cases: not required.
   The stage 3 `kill -9` divergence is a known Corrosion bug, so don't chase it here.
9. `up.sh` / `down.sh` are unchanged for the user. After down, the host is clean: no edge containers, nothing on `127.0.0.1:80`, no routes.

## Risk points: check these first, in this order, and stop early if one is a blocker
1. Two nspawn containers with `privateNetwork = false` both bind `127.0.0.1:80` with `SO_REUSEPORT`.
   - Linux only groups reuseport sockets with the **same effective UID**, so `DynamicUser` (a different UID per container)
     will fail with EADDRINUSE. Use a fixed UID, set the same in both edges.
   - Check that extra-container accepts host networking, and that the host has nothing on :80 when up.sh starts.
2. Corrosion agents in the host namespace join the worker cluster: gossip edge ↔ worker in both directions, and a write on
   worker1 shows up on both edges.
3. hyper CONNECT on both sides (server-side upgrade in the worker, client CONNECT + `handshake` over the upgraded IO in the
   edge), with fallback before any request bytes are sent.
4. Turning off worker forwarding keeps worker → VM (local bridge) and host ↔ worker (transit) working.

## Constraints
- Keep the one-table flake approach. Generate edge configs, ports and bootstrap lists, with no per-edge copy-paste.
  Edges are a second small table next to `workers`.
- Mark every shortcut as `# shortcut:` / `// shortcut:` (anycast stand-in, plaintext backhaul, static worker map,
  no pooling, local RR only).
- `verify.sh` stays fast and covers criteria 1–7 (failover and validation sections may use sudo, as before). Criterion 8 goes in `storm.sh`.

## Out of scope
- Real anycast/BGP, and choosing the nearest or least-loaded worker (Fly's edge does that; we do RR).
- WireGuard/TLS and auth on the backhaul.
- TLS termination at the edge.
- HTTP/2, websockets beyond what raw piping happens to allow, and health checks or ejection.
- Moving the edges off the host netns.
- Fixing the Corrosion divergence bug (reported as superfly/corrosion#596).
