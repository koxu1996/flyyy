## Goal
Stage 2 of the spike (stage 1: `PROMPT.md`, `NOTES.md`, commit 416a729).
Add a small Rust HTTP reverse proxy on each worker that routes requests by app-style vhost
(`Host` header) to the VMs of that app running on the same worker, using a static config.
A second app with a different image is added, so the vhost routing is actually exercised.
Plain HTTP on :80 only. The question is still feasibility; this is not a production proxy.

## Target topology (changes from stage 1 in bold)
host
├── containerd + devmapper (unchanged)
└── 3 × nspawn workers (unchanged)
    ├── **proxy.service: listens on 0.0.0.0:80 inside the worker (10.99.N.2:80 from the host)**
    │   **`<app>.flyyy.localhost` → round robin over that worker's VMs of that app**
    ├── 2 × `whoami` VMs: a (.10), b (.11) on every worker (unchanged)
    └── **2 × `echo` VMs: c (.12), d (.13) on worker1 and worker2 only → 10 VMs total**

## Second app: `echo`
- Image `hashicorp/http-echo`, linux/arm64, pinned by digest like whoami. It listens on :5678,
  which also tests a non-80 upstream port.
- Per-VM Cmd override `-text=<worker>-<vm>` (e.g. `-text=worker1-c`), so responses show which
  instance answered. This means image args move from per-worker to per-VM (`/spike/<vm>.args`).
- Snapshots: one per VM from that VM's app image, and both images are imported into the same pool.
- The stage 1 init and pipeline must work for this image unchanged; if they don't, that's a finding.

## Routing (static, generated by Nix from the same worker/VM table as stage 1)
- The worker/VM table gets per-VM `app` and the app table gets image, port and optional Cmd
  override. The vhost is `<app>.flyyy.localhost`, and its upstreams are that worker's VMs with
  that app. A worker with no VMs of an app has no route for it.
- Config file, one line per vhost: `<vhost> <ip:port> [<ip:port> ...]`. No serde, no TOML.
  It's passed as an argument, and changing it means restarting the unit (no hot reload).
- Match on Host without the port and case-insensitively. Unknown host → 404. Missing Host → 400.
- Round robin per vhost (an atomic counter is enough).
  `// shortcut: local-only round robin, replace with real balancing/placement in a later stage`.
- On a **connect** error, try the next upstream once more round the list (safe, since nothing
  was sent yet). If all upstreams fail → 502. No retries after the request was sent, and no health checks.

## Proxy requirements
- Rust, built in the flake with `rustPlatform.buildRustPackage` + a committed `Cargo.lock`.
- Dependencies: tokio + hyper (+ hyper-util / http-body-util if needed). Nothing else
  unless it is unavoidable; justify any extra crate in NOTES.md. No hand-written HTTP parsing.
- HTTP/1.1 only. Stream request/response bodies (no full buffering).
- Pass the original Host header upstream and add `X-Forwarded-For`.
- One log line per request (method, host, path, status, upstream, latency) to stdout → journal.
- Runs as a non-root user (bind to :80 with `AmbientCapabilities=CAP_NET_BIND_SERVICE`).

## Success criteria (all must pass)
1. Stage 1 `verify.sh` checks still pass (direct VM access via 10.100.N.x).
2. Note that curl resolves `*.localhost` to 127.0.0.1 on its own, so tests must use
   `--connect-to whoami.flyyy.localhost:80:10.99.N.2:80` (or `-H Host:`).
   Extended `verify.sh`:
   - every worker: 4 requests to `whoami.flyyy.localhost` alternate `workerN-a` / `workerN-b`;
   - worker1, worker2: 4 requests to `echo.flyyy.localhost` alternate `workerN-c` / `workerN-d`;
   - worker3: `echo.flyyy.localhost` → 404 (app not placed there).
3. Unknown Host → 404. Direct VM checks (criterion 1) cover all 10 VMs.
4. With `firecracker@a` stopped in one worker, all requests to that worker still return 200
   (served by `b`). With both stopped → 502. After restarting them, round robin resumes.
5. `up.sh` / `down.sh` still work unchanged from the user's point of view, and the host is clean after down.

## Constraints
- One small crate (`proxy/`, ideally a single `main.rs`).
- Same flake and the same "generate from one table" approach, with no per-worker copy-paste.
- Must still fit comfortably in host memory: 10 × 128 MiB guests.
- Mark every shortcut as `# shortcut: <limit>, <when to upgrade>` (or `// shortcut:` in Rust).

## Out of scope
TLS, dynamic config / service discovery, health checks, weighted or least-conn balancing,
retries after the request was sent, cross-worker routing, HTTP/2, websockets, rate limiting,
metrics, a host-level entry point.

## Deliverables
- `proxy/` crate, flake changes, extended `verify.sh`.
- A "Stage 2" section in `NOTES.md` (≤ ½ page): what worked and what didn't, proxy RSS, host memory
  for all 10 VMs, rough added latency (direct VM vs via proxy, e.g. 1000 sequential curls, or
  `oha`/`wrk` if already in nixpkgs),
  and the top 3 problems for taking this further.
